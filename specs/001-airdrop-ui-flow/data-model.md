# Data Model & State Management

**Feature**: `001-airdrop-ui-flow`

## 1. Frontend Data Entities

These entities define the shape of data handled by the Next.js application.

### 1.1. Whitelist Data (JSON Schema)
The source of truth for the airdrop distribution.
```typescript
interface WhitelistEntry {
  address: string; // 0x...
  amount: string;  // In Wei (18 decimals)
}

interface WhitelistDatabase {
  [address: string]: WhitelistEntry;
}
```

### 1.2. Merkle Artifacts
Data generated by the Admin during the transition phase.
```typescript
interface MerkleArtifact {
  merkleRoot: string; // bytes32 hex string
  totalAmount: string; // Total tokens in airdrop
  claims: {
    [address: string]: {
      index: number;
      amount: string;
      proof: string[]; // Array of bytes32 hex strings
    }
  }
}
```

### 1.3. User UI State
Global state for the User view (`/user`).
```typescript
interface UserState {
  phase: 'COLLECTION' | 'CLAIM'; // Fetched from API or Contract
  address: string | undefined;   // From Wallet
  isWhitelisted: boolean;        // Derived from API check
  allocation: string | null;     // Displayed amount
  hasClaimed: boolean;           // Derived from Contract Read
}
```

## 2. On-Chain Storage Mapping

Mapping frontend concepts to `MerkleAirdrop.sol` storage.

| Frontend Concept | Contract Storage | Notes |
|------------------|------------------|-------|
| Merkle Root | `bytes32 public merkleRoot` | Updated by Admin via `updateMerkleRoot` |
| Claim Status | `mapping(address => bool) public hasClaimed` | Updated upon successful `claim` |
| Token Address | `IERC20 public immutable airdropToken` | Set at deployment |

## 3. API Routes (Next.js)

Simple internal APIs to interface with the local JSON file storage (MVP).

### 3.1. `POST /api/whitelist/join`
- **Input**: `{ address: string }`
- **Logic**: 
  - Validate address format.
  - Check duplicates.
  - Randomly generate amount (min-max range).
  - Append to `backend/whitelist.json` (or local mock file for pure frontend MVP).
- **Output**: `{ success: true, allocation: string }`

### 3.2. `GET /api/whitelist/status`
- **Input**: `?address=0x...`
- **Output**: `{ isWhitelisted: boolean, allocation: string, proof?: string[] }`
